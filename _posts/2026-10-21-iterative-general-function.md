## 迭代改进

计算机最初以数值计算为目的被发明至今，已经产生了翻天覆地的变化。稍微了解一些计算机组成原理的朋友都知道，加法器是构成计算机的基础电路部件之一。

就像在学习四则运算时，我们从加法演进到减法和乘法是自然且直觉的。这一点体现在计算数学题时，我们通常倾向于直接计算出它们的结果，而面对除法和根号时，我们通常青睐$\frac{2}{3}$、$\sqrt{ 2 }$的写法，而不是$0.666\dots$和$1.414\dots$ ，这直白地昭示了这些记号所代表的运算的复杂性。

而想要进行精确的数值运算，计算机必须要能够解决这些问题，迭代法便是诸多解决方案中最自然普遍的一种。

就像搭积木一样，我们希望能用加、减、乘来构建出除法。由于$\frac{B}{A} = B \times \frac{1}{A}$，我们可以先求一个数的倒数，再去调用乘法。

秉持大胆假设，小心求证的思想，对于$\frac{1}{A}$或许可以先猜测一个值$x$。这个值和真值间会产生误差（这里使用**相对误差**，因为我们此时只关心**有效数字**，不是绝对差距，而且相对误差可以消除除法——即我们要实现的新积木）：

$$
\begin{align}
e &= \frac{\vert \frac{1}{A} - x \vert}{\vert\frac{1}{A}\vert} \\ 
 &=  \vert 1- Ax\vert
\end{align}
$$

对于精度$\epsilon$，我们可以认为，如果$e \leq \epsilon$，$x$就是正确的。因此我们就得到了一个判断我们猜的是否正确的函数`close()`:

```python
def close(x):
	return abs(A*x-1) <= epsilon
```

于是，我们立刻想到，希望可以找到一个函数$F(x_{n}) = x_{n+1}$，使得新值的误差相比原来的下降，这样我们就可以迭代了：

```python
def improve(x):
	while not close(x):
		x = F(x)
	return x
```

关于如何得到$F(x)$，历史上我们有很多方法，比如大名鼎鼎的牛顿迭代法和自举法。但这里我想要避开导数和级数，先提供两个我觉得更符合直觉的办法。

### 方法一

我们希望误差逐步变小，所以构造$e_{n+1} = e_{n}^2$，不妨假设 $0<Ax_{n}<1$ 现在反解$x_{n+1}$:

$$
e_{n+1} = 1- Ax_{n+1} 
$$


$$
\begin{align}
x_{n+1} &= \frac{1-(e_{n+1})}{A} \\
&= \frac{1-(e_{n}^2)}{A}
\end{align}
$$

这里面只有$\frac{1}{A}$是未知的，利用$e_{n}$的定义：

$$
\frac{1}{A} = \frac{x_{n}}{1 - e_{n}}
$$

所以：

$$
\begin{align}
x_{n+1} &= x_{n} \frac{1-e_{n}^2}{1-e_{n}} \\
&= x_{n} (1+e_{n})\\
&= x_{n} (2 - Ax_{n})
\end{align}
$$

也就是：

```python
def F(x):
	return x*(2-A*x)
```

这样只要给定`A, epsilon`和合适的初始值`x0`就可以得到我们想要的结果了。


### 方法二

假设真实值$r = \frac{1}{A}$，且迭代到最后$x \approx \frac{1}{A}$，则$r-x = \frac{1-Ax}{A}\approx x(1-Ax)$.

所以更新时修正为$x_{new} = x + (r-x) = x +x(1-Ax)=x(2-Ax)$.

这个方法是一种代数直觉：残差 $1-Ax$ 是无量纲的相对误差，乘上当前估计 $x$ 就得到修正量。


## 作为通用方法的函数

利用四则运算作为积木，想要搭建出求根的迭代式 $x_{n+1} = \frac{1}{2}\left( x_{n}+\frac{A}{x_{n}} \right)$ 也不困难，事实上这个推导早在近四千年前就被发现了，称为巴比伦求根法。

然而在计算机编程中，我们不想每次都重新定义迭代函数，我们想要构建出表示通用计算方法的函数，它们与具体调用哪些函数无关。循着这种设计思路，高级编程语言允许我们把自定义的函数**作为参数**传入：

```python
def improve(update,close,guess=1):
	while not close(guess):
		guess = update(guess)
	return guess
```

然而无论是倒数还是求根，都需要两个输入参数：目标值`A`和记录迭代过程的`guess`（之前推导时把`A`放到全局变量里的行为不利于封装和调用），我们的通用函数`improve`只接受一个参数。此时我们并不需要修改这个通用函数——这正是其通用性的体现——而是把函数放进另一个函数的体内进行封装：

```python
# 先定义一个更通用的close判定函数，即猜测值与目标值的差距
def close(x, y, epsilon=1e-15):
     return abs(x-y) <= epsilon
     
def reciprocal(A):
	def reciprocal_update(x):
		return x*(2-A*x)
	def reciprocal_close(x):
		return close(A*x,1)
	return improve(reciprocal_update,reciprocal_close)
```

用同样的方法，可以很轻易地构造求根函数：

```python
def sqrt(A):
	def sqrt_update(x):
		return (x+A/x)/2
	def sqrt_close(x):
		return close(x,A/x)
	return improve(sqrt_update,sqrt_close)
```

这两个例子很好地体现了通用函数的“**通用性**”。[John DeNero](https://www.denero.org/)所著的[Composing Programs](https://composingprograms.com/)一书中指出，这种设计体现了计算机科学中两个至关重要的思想：

1. 命名和函数使得我们可以抽象掉大量的复杂性。每个函数的定义都是简单的，整个计算过程却精巧而复杂。
2. 这些小组件能够组成复杂过程，得益于编程语言（例如Python）拥有通用的求值流程。理解程序对这个求值流程的解释有助于我们检查和验证我们创造的这些过程。

## 函数作为返回值

当数学家发明了新的数学方法，我们总希望能快速用计算机实现它，以替代烦闷的人工计算。

牛顿法提供了通用的改进对于可微函数零点猜测的办法，即沿着猜测点的切线（也就是线性近似）逼近，最终找到函数的零点。对于前述的倒数和求根两例，其数学本质和牛顿法是相似的，但现在我们又可以升级通用函数了：

```python
def find_zero(f,df):
	def near_zero(x): 
		return close(f(x), 0) 
	return improve(newton_update(f,df), near_zero)
```

例如求根，定义$f(x) = x^2 - A$，找到这个函数的零点就等于求出了$\sqrt{A}$，所以：

```python
def sqrt(A):
	def f(x):
		return x*x-A
	def df(x):
		return 2*x
	return find_zero(f,df)
```

这比之前看上去又简洁了不少。

但我们注意到，这种写法要求`newton_update(f,df)`这个函数通过输入原函数和导数，要返回一个`update`函数，这可以做到吗？当然，编程语言允许函数的返回值本身也是函数，这样程序就能获得更强的表达能力，我们可以这样实现：

```python
def newton_update(f,df):
     def update(x):
         return x-f(x)/df(x)
     return update
```

简单明了，不是吗？

牛顿法本身具有一定的局限性，比如初始猜测要足够接近我们期望获得的零点，函数本身也要满足一些条件，不过后续数学家也对它做了一些改进。作为程序编写者，我们总是从数学家那里获得更先进的技巧，并想要把它们变成通用函数来实现。

## 函数是一等公民

我们通过定义一系列函数，精巧地实现了各种复杂的计算过程。这完全得益于编程语言允许我们把计算方法本身作为显式元素表达出来，并可以像对待其它计算元素一样操作它。

一般来说，编程语言会对计算元素的操作方式施加各种限制。限制最少的元素，可以被称为**一等公民**，它通常享有以下权利：

1. 可以作为变量绑定到标识符；
2. 可以作为参数传给函数；
3. 可以作为函数的结果返回；
4. 可以存储在数据结构中；

在Python中，函数是一等公民，在现代c++（c++11以后）中也是。

> 如果你想问为什么早期c++没有赋予函数一等公民权利，这其实是个有点复杂的话题。
> 对于早期的高级编程语言（尤其是Java）来说，函数必须绑定在对象上，传递函数本身是不自然的，而这种限制也使得一个运行在单机上的复杂程序不容易出现错误。
> 而现在Python等语言通过更改一个对象所引用的函数，就能动态改变对象的行为，非常有利于提升并发计算和分布式计算的效率，在现代业务中获得了青睐。

作为程序员，我们应该留意程序中**潜在的底层抽象**，并用它们创造更强大更泛化的抽象。虽说我们并不比总是用最抽象的方式来写程序——“高手懂得选择与任务相称的抽象层次”——但我们可以利用这种思维方式，在新的场景中快速利用那些底层抽象。
