> 贪婪策略（Greedy Strategy）的代码实现往往极其简单，但它的核心难点在于**证明**。局部最优并不总能导向全局最优，在应用贪婪策略后，我们必须进行严格的正确性证明，绝不能理所当然地认为它成立。
{: .prompt-info }

贪婪策略是一种在每一步选择中都采取在当前状态下最好或最优（即最有利）的选择，从而希望导致结果是全局最好或最优的算法策略。

* **求解过程**：一个多步判断的过程，每一步都做出局部最优选择。
* **优势**：算法设计简单、执行速度快。能够为一些问题找到最优解，或者为复杂问题快速提供一个可行的近似解。
* **不足**：局部最优并不总能导向全局最优。使用贪婪策略后，必须进行严格的证明（通常使用反证法和交换论证法）。


## 找零问题 (Coin Changing Problem)

> **问题描述**：给定 $m$ 种面值为 $C_1 < C_2 < \dots < C_m$ 的硬币，每种数量充足，要求用最少的硬币数凑出总金额 $n$。

### 收银员算法

在每一步，总是选择**不超过剩余待付金额的、面值最大的硬币**。

**算法伪代码**：

```text
Algorithm CoinChange(C, n)
输入: 硬币面值集合 C，目标金额 n
输出: 凑出 n 的硬币集合 S

1. S ← ∅
2. while n ≠ 0 do
3.   找到满足 C_k ≤ n 的最大面值硬币 C_k
4.   if 找不到 then return 无解
5.   n ← n - C_k
6.   S ← S ∪ {C_k}
7. return S

```

### 贪婪选择的局限性与证明

收银员算法并非对所有面值组合都最优。例如，当硬币面值为 $\{1, 5, 7, 10\}$，要凑 $19$ 元时：

* 贪婪解：$10 \times 1 + 7 \times 1 + 1 \times 2 = 19$（共 $4$ 枚）。
* 最优解：$7 \times 2 + 5 \times 1 = 19$（共 $3$ 枚）。

但在特定的面值系统下（如我们日常使用的 $\{1, 5, 10\}$），该算法是最优的。

{% capture proof_content_1 %}
**定理**：对于面值为 $\{1, 5, 10\}$ 的情况，收银员算法给出的解是最优解。

**证明（反证法）**：
设**最优解**为 $(x, y, z)$，分别代表 $10$ 元、$5$ 元、$1$ 元硬币的数量。
设**贪婪解**为 $(x', y', z')$。总金额相等：$10x + 5y + z = 10x' + 5y' + z'$。

**第一步：证明 $x = x'$**
根据贪婪算法优先选择最大面值的特性，贪婪解中 $10$ 元硬币的数量不会少于任何其他解，故 $x' \ge x$。
假设 $x' > x$（即 $x' - x \ge 1$）：
由总金额等式可推导：$5y + z = 10(x' - x) + 5y' + z'$
因为 $x' - x \ge 1$，且 $y', z' \ge 0$，所以必然有 $5y + z \ge 10$。
分析最优解中 $(5y+z)$ 的组成情况：

* 若 $y \ge 2$：可用 $1$ 个 $10$ 元替换 $2$ 个 $5$ 元，硬币总数减少 $1$，与“$(x,y,z)$ 是最优解”矛盾。
* 若 $y = 1$ 则 $z \ge 5$：可用 $1$ 个 $10$ 元替换 $1$ 个 $5$ 元和 $5$ 个 $1$ 元，硬币总数减少 $5$，矛盾。
* 若 $y = 0$ 则 $z \ge 10$：可用 $1$ 个 $10$ 元替换 $10$ 个 $1$ 元，硬币总数减少 $9$，矛盾。
所有情况均导出矛盾，故假设不成立，结合 $x' \ge x$ 可得 $x = x'$。

**第二步：证明 $y=y'$ 及 $z=z'$**
在 $x = x'$ 基础上，用完全相同的替换思路可证 $y = y'$。
当 $x=x'$ 且 $y=y'$ 时，代入总金额等式，显然可得 $z=z'$。
贪婪解与最优解完全一致，得证。

## 活动选择问题 (Interval Scheduling)

> **问题描述**：给定一个包含 $n$ 项活动的集合 $S=\{1, 2, \dots, n\}$。每项活动 $j$ 都有一个开始时刻 $s_j$ 和结束时刻 $f_j$。目标是找出一个由互相兼容（时间不重叠）的活动组成的**最大子集**。

通常我们可以先尝试提出贪婪的构想，然后尝试证明可行者。往往也只有一种能导向最优：

* **最早开始时刻优先**：非最优。可能选中一个开始早但耗时极长的活动，导致错过多个短活动。
* **最短持续时间优先**：非最优。可能选中一个处于中间位置的短活动，但它恰好阻断了首尾两个长活动。
* **最少冲突数量优先**：非最优。
* **最早结束时刻优先**：**最优策略**。它能保证总能为后续的活动留下最多的可用时间。

**算法伪代码**：

```text
Algorithm ActivitySelection(s, f)
1. 将所有活动按结束时刻 f_j 升序排序
2. A ← {活动 1}  // 选择结束最早的第一个活动
3. last_f ← f_1
4. for j = 2 to n do
5.   if s_j ≥ last_f then  // 如果兼容
6.     A ← A ∪ {活动 j}
7.     last_f ← f_j
8. return A

```


使用**参数交换**策略可以证明“最早结束时刻优先”贪婪算法得到的是最优解。其核心思想是：证明任何一个最优解，都可以通过一系列的“交换”操作，转化为贪婪解，且解的质量不降低。

{% capture proof_content_2 %}
**定理**：“最早结束时刻优先”贪婪算法得到的是最优解。

**证明**：
设贪婪解为 $G = \{i_1, i_2, \dots, i_k\}$（按结束时间排序）。
设存在一个最优解 $O = \{j_1, j_2, \dots, j_m\}$（按结束时间排序），且 $m \ge k$。
假设在所有最优解中，$O$ 是与 $G$ 具有**最长公共前缀**的解。
假设贪婪解不是最优的，即 $G \neq O$。

设两个解序列中第一个不同的活动发生在第 $r+1$ 个位置，即前 $r$ 个活动完全相同：
$i_1=j_1, i_2=j_2, \dots, i_r=j_r$

分析第 $r+1$ 个活动：

* 贪婪解选择了 $i_{r+1}$，这是在与前 $r$ 个活动兼容的所有活动中，**结束时间最早**的。
* 最优解选择了 $j_{r+1}$，它同样与前 $r$ 个活动兼容，因此其结束时间必然不早于 $i_{r+1}$：$f(i_{r+1}) \le f(j_{r+1})$。

我们构造一个新的解 $O'$：将 $O$ 中的 $j_{r+1}$ 替换为 $i_{r+1}$。
因为 $f(i_{r+1}) \le f(j_{r+1})$，所以 $i_{r+1}$ 必然不会与 $O$ 中 $j_{r+1}$ 之后的任何活动产生冲突。
因此，$O'$ 仍然是一个包含 $m$ 个活动的兼容子集，即 $O'$ 也是一个最优解。

**导出矛盾**：
新构造的最优解 $O'$ 与贪婪解 $G$ 的公共前缀长度变成了 $r+1$。这比原最优解 $O$ 的公共前缀长度 $r$ 更长，与“$O$ 是具有最长公共前缀的最优解”假设矛盾！
因此，贪婪解必定与最优解包含相同数量的活动。

## 最小延迟调度 (Scheduling to Minimize Lateness)

> **问题描述**：一台处理器需要串行执行 $n$ 个任务。任务 $i$ 耗时 $t_i$，截止时限为 $d_i$。如果在 $s_i$ 开始，完成时间为 $f_i = s_i + t_i$，延迟为 $l_i = \max\{0, f_i - d_i\}$。目标是安排执行次序，使**最大延迟** $\max\{l_i\}$ 最小化。

### 逆序对

* **最短任务优先** / **最小松弛时间优先**：反例易得，均非最优。
* **紧急任务优先**：按任务的时限 $d_i$ 升序安排。这是**最优策略**。

我们同样可以使用**交换论证法**证明，但这次引入**逆序 (Inversion)** 的概念。
定义：如果任务 $j$ 在任务 $i$ 之前执行，但 $d_i < d_j$，则称 $(i, j)$ 构成一个逆序。

{% capture proof_content_3 %}
**定理**：“紧急任务优先”算法得出最优解。

**证明**：

1. **观察**：贪婪解（严格按 $d_i$ 排序）中不存在任何逆序。
2. **假设**：设 $S^*$ 是一切最优解中，逆序数最少的一个。如果 $S^*$ 逆序数为 $0$，则它就是贪婪解，证明结束。
3. **消除逆序**：如果 $S^*$ 中存在逆序，必然存在一对**相邻的**逆序任务 $(j, i)$（$j$ 在前，$i$ 在后，且 $d_i < d_j$）。
我们交换它们的执行顺序，得到新调度方案 $S'$。
4. **分析交换影响**：
* 任务 $i$ 提前了，其延迟 $l'_i \le l_i$，不会增加。
* 任务 $j$ 推后了，完成时间变成了原本 $i$ 的完成时间 $f_i$。其新延迟 $l'_j = \max\{0, f_i - d_j\}$。由于 $d_i < d_j$，所以 $f_i - d_j < f_i - d_i \le l_i$。即交换后 $j$ 的延迟严格小于交换前 $i$ 的延迟。
* 其他任务的时间均未改变。

5. **结论**：交换后，整个系统的最大延迟没有增加，所以 $S'$ 仍然是最优解。但 $S'$ 的逆序数比 $S^*$ 减少了 $1$。这与“$S^*$ 是逆序数最少的最优解”矛盾！故最优解不能包含逆序，贪婪解即为最优解。
{% endcapture %} {% include components/collapsible.html title="紧急任务优先策略最优性证明" content=proof_content_3 %}


## 图论中的贪婪算法

贪婪策略在图论中有两个经典问题：**最小生成树 (MST)** 和 **单源最短路径 (SSSP)**。
它们的各种解由于太过有名，下面只简单介绍核心思想。

### 最小生成树 (MST) 

MST 算法的正确性都依赖于两个基础的结构性特征（假设边权互异）：

1. **切割性质 (Cut Property)**：对于任意切割，权重最小的横切边必然属于 MST。
*(反证：如果不包含，加入它会形成环，环上必有另一条更重的横切边，替换即可得到更小的生成树)*。
2. **环路性质 (Cycle Property)**：对于图中任意环路，权重最大的边不可能属于任何 MST。

基于这两点，诞生了三种经典的贪婪算法：

* **Prim 算法**：从顶点出发，维护一个树集 $S$。每次贪婪选择连接 $S$ 内外权值最小的边（直接应用**切割性质**）。时间复杂度 $\Theta(m \log n)$。
* **Kruskal 算法**：按边权升序遍历所有边，如果不构成环就加入（利用并查集检测环，应用**切割性质与环路性质**）。时间复杂度 $\Theta(m \log n)$。
* **Reverse-Delete 算法**：按边权降序遍历，只要不破坏连通性就删边（直接应用**环路性质**）。

### 单源最短路径：Dijkstra 算法

虽然 Dijkstra 与 Prim 伪代码极其相似，但贪婪决策的目标截然不同。Dijkstra 仅适用于**非负权图**。

* **Prim 更新规则**：`cost[z] = w(u, z)`。只关心连接新顶点的单条边权重。
* **Dijkstra 更新规则**：`d[z] = d[u] + w(u, z)`。关心的是从源点出发的**累积路径长度**。


## 霍夫曼编码 (Huffman Coding)

用于无损数据压缩的贪婪算法。目标是为字符分配**前缀码**，使得加权路径长度 $\sum (\text{频率} \times \text{编码长度})$ 最小化。

**算法逻辑（自底向上建树）**：
每次贪婪地选择当前频率最小的两个节点进行合并，作为新节点的左右子树，新频率为两者之和。重复此过程直到只剩一个根节点。时间复杂度 $\Theta(n \log n)$。

其正确性依然可以通过**交换论证法**证明：一定存在一棵最优编码树，使得频率最低的两个字符互为兄弟节点，且位于树的最深层。

这个也不多赘述了。

## 背包问题

贪婪算法虽好，但并非万能的。对于经典的 **0-1 背包问题**，无论是优先重量最小、价值最大还是价值密度（性价比）最大，都**无法保证**得到最优解。这是一个 NP-hard 问题，需要借助动态规划来解决。

但是，如果条件放宽为 **分数背包问题 (Fractional Knapsack)**（物品可以被分割），那么“**最大价值密度优先**”的贪婪策略就变成了最优解。证明略。
